Prerequisites

Before deploying the Web Charging Gateway, a PortaBilling administrator must complete the following configuration in PortaBilling. These steps are performed in the PortaBilling web interface and are required for the gateway to authorize and charge users successfully.

For full PortaBilling configuration documentation, see https://docs.portaone.com/

PortaBilling Configuration Checklist​

1. Register the Gateway as a Trusted Node (NAS Entry)​

The gateway communicates with PortaBilling's RADIUS server. PortaBilling only accepts RADIUS requests from trusted nodes (also called NAS — Network Access Server entries).

  • In PortaBilling, create a Node entry for the gateway
  • Set the NAS IP to the NAT gateway IP address of the Kubernetes cluster where the gateway is deployed

Important: The NAS IP must be the cluster's external NAT gateway IP — not the pod IP or service IP. If the IP does not match, PortaBilling will silently discard all incoming RADIUS requests from the gateway.

  • Set a RADIUS Secret on the Node — this must match the RADIUS_SECRET value in the gateway's configuration file
    • Use a strong secret: mix of uppercase letters, lowercase letters, and numbers
    • Maximum length: 32 characters

2. Define the Service Catalog​

Create the billing building blocks that define what services exist and how they are priced.

  • Destinations — rate codes that match the item field in API requests (e.g., KWh, Token, MB)
  • Destination Group Sets — groups of destinations used in tariff lookups
  • Services — define the service type (e.g., a Quantity-based service for energy, a Netaccess service for data sessions)
  • Tariffs — define pricing: the rate applied per unit of each destination, for both customer billing and vendor cost

3. Create Products and Usage Policies​

  • Products — bind a service and tariff together; assigned to customers
    • In the product's Usage Charges section, assign Access Codes to each service
    • The access_code field in API requests must exactly match the Access Code defined here
    • Example: a product for EV charging might have two usage charges — one with access code ENERGY for kWh consumption, and one with access code SESSION for concurrent session slots
  • Volume Discount Plans / Quotas (optional) — enforce fair-use limits or bundle quotas; the gateway enforces these in real time during authorization

4. Provision Customers and Accounts​

End-users in PortaBilling are represented as Customers with Accounts.

  • Create a Customer for each billing entity (e.g., a company or individual)
  • Create an Account under the customer for each service user
    • The Account ID is what your application will pass as the user_id in API requests
    • The Account ID can be any unique identifier meaningful to your application: an email address, a vehicle VIN, a license plate number, a device ID, or any secure token
  • Assign the correct Product to the account
  • Ensure the account has sufficient balance or credit limit for the services it will use

Network Requirements​

ProtocolPortDirectionPurpose
UDP1812Gateway → PortaBilling RADIUSAuthorization (Access-Request)
UDP1813Gateway → PortaBilling RADIUSAccounting (Accounting-Request)
HTTP/HTTPSAs configuredClient → GatewayREST API access

Ensure firewall rules permit UDP traffic on ports 1812 and 1813 from the gateway's NAS IP to the PortaBilling RADIUS server.
