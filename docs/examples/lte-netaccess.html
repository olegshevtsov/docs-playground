Example: LTE / 5G NETACCESS

This example shows how to report data session usage for LTE or 5G subscribers using the Web Charging Gateway. Two approaches are covered: using the standard /services/{user_id}/charges endpoint with service_type: Netaccess, and using the 3GPP Nchf-compatible /nchf-chargingdata endpoint.

Approach A: Standard Charges Endpoint (Netaccess)​

Use this approach for straightforward LTE/5G data session billing.

Scenario: An LTE subscriber with MSISDN 447700900001 completes a data session. The platform reports the bytes transferred and charges the subscriber.

PortaBilling Setup​

  • Account ID: 447700900001 (MSISDN or any unique identifier)
  • Product with usage charge: access code DATA → tariff with destination NETACCESS

Charge for a Data Session​

curl -X POST https://<host>/services/447700900001/charges \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "perform_authorization": false,
    "service_elements": [
      {
        "session_id": "lte-session-pdn-001",
        "service_type": "Netaccess",
        "access_code": "DATA",
        "item": "NETACCESS",
        "units": 102400,
        "comment": "LTE data session - 100MB"
      }
    ]
  }'

Response:

{
  "success": true,
  "service_elements": [
    {
      "timestamp": "2024-05-17 18:00:00",
      "billing_session_id": "D5E6F789 4C5C21EF D47D5CBE AD918421",
      "session_id": "lte-session-pdn-001",
      "service_type": "Netaccess",
      "access_code": "DATA",
      "item": "NETACCESS",
      "user_id": "447700900001",
      "i_user": "54321",
      "units": 102400,
      "charged_units": 102400,
      "charged_amount": 0.10
    }
  ],
  "failed_service_elements": [],
  "unprocessed_service_elements": [],
  "error": "None",
  "error_detail": "None"
}

Pre-Authorize a Data Session​

For real-time quota enforcement (prevent the subscriber from consuming data they cannot pay for), authorize before the session starts:

curl -X POST https://<host>/services/447700900001/auth \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "service_elements": [
      {
        "session_id": "lte-session-pdn-002",
        "service_type": "Netaccess",
        "access_code": "DATA",
        "item": "NETACCESS",
        "units": 524288,
        "lock_period": 3600,
        "comment": "Authorize 512MB for LTE session"
      }
    ]
  }'

Approach B: Nchf Endpoint (3GPP 5G Interface)​

Use this approach if your platform natively generates 3GPP Nchf ChargingDataRequest payloads, or if you want to use the 3GPP schema for compatibility.

The gateway accepts an Nchf-formatted request, extracts the relevant billing fields, and translates them into a PortaBilling RADIUS Accounting-Request.

Note: The gateway processes only the fields that map to PortaBilling's RADIUS dictionary. Additional 3GPP-specific fields in the request are accepted but not acted upon for billing. Refer to the live Swagger at /docs for the full accepted schema.

Charge via NCHF​

curl -X POST https://<host>/nchf-chargingdata \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "subscriberIdentifier": "msisdn-447700900001",
    "nfConsumerIdentification": {
      "nfName": "SMF-01",
      "nfIPv4Address": "10.0.0.5",
      "nFType": "SMF"
    },
    "multipleUnitUsage": [
      {
        "ratingGroup": 1,
        "usedUnitContainer": [
          {
            "serviceSpecificInfo": [
              {"value": "NETACCESS"}
            ],
            "totalVolume": 1048576
          }
        ]
      }
    ]
  }'
FieldDescription
subscriberIdentifierIdentifies the PortaBilling account. Format: msisdn-<number> or imsi-<imsi>
nfConsumerIdentificationIdentifies the 5G network function sending the request (informational)
multipleUnitUsage[].usedUnitContainer[].totalVolumeBytes consumed in this rating group
serviceSpecificInfo[].valueMaps to the service type in PortaBilling (e.g., NETACCESS)

Response: Standard AccountingResponse format — same as the /services/{user_id}/charges response.

Choosing Between Approach A and B​

Approach A (Standard endpoint)Approach B (Nchf endpoint)
Best forCustom-built or non-3GPP platformsPlatforms generating 3GPP-native payloads
SchemaSimple, PortaBilling-specific JSON3GPP Nchf JSON
Authorization supportYes (/auth endpoint)No (accounting only)
Full schema in SwaggerYesYes (/docs)

For most new integrations, Approach A is recommended for its simplicity and full support of the authorize → charge → unlock flow.
