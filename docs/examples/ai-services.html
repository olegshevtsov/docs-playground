Example: AI Service Monetization

This example shows how to bill users for AI service consumption — such as LLM tokens, API queries, or voice engine minutes — using the Web Charging Gateway.

Scenario: An AI API platform charges users per token consumed during inference. After each request, the platform reports the token count and charges the user's account.

PortaBilling Setup​

The PortaBilling administrator should configure:

  • Account per user (e.g., user@example.com)
  • Product with usage charges:
    • Access code TOKEN → tariff with destination Token (price per 1000 tokens, or per token)
  • Optionally: a Volume Discount Plan or quota to enforce a free-tier token limit

Pattern 1: Charge After Inference (No Pre-Authorization)​

The simplest pattern — charge for tokens after the AI call completes, without pre-authorization. Suitable when you trust the billing to report accurately and are comfortable with small overdraft risk (e.g., one inference request's worth).

curl -X POST https://<host>/services/user@example.com/charges \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "perform_authorization": false,
    "service_elements": [
      {
        "session_id": "inference-req-abc123",
        "service_type": "Quantity",
        "access_code": "TOKEN",
        "item": "Token",
        "units": 1542,
        "comment": "GPT inference - user prompt + completion"
      }
    ]
  }'

Response:

{
  "success": true,
  "service_elements": [
    {
      "timestamp": "2024-05-17 15:30:00",
      "billing_session_id": "A1B2C461 4C5C21EF D47D5CBE AD918421",
      "session_id": "inference-req-abc123",
      "service_type": "Quantity",
      "access_code": "TOKEN",
      "item": "Token",
      "user_id": "user@example.com",
      "i_user": "67890",
      "units": 1542,
      "charged_units": 1542,
      "charged_amount": 0.05
    }
  ],
  "failed_service_elements": [],
  "unprocessed_service_elements": [],
  "error": "None",
  "error_detail": "None"
}

Pattern 2: Authorize Before Inference, Charge After​

Use this pattern when you want to guarantee the user has sufficient balance before spending compute resources on their request. PortaBilling locks the requested token budget. If the actual usage is less, the excess is released when you charge.

Step 1: Authorize (before running inference)​

curl -X POST https://<host>/services/user@example.com/auth \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "service_elements": [
      {
        "session_id": "inference-req-xyz456",
        "service_type": "Quantity",
        "access_code": "TOKEN",
        "item": "Token",
        "units": 4096,
        "lock_period": 30
      }
    ]
  }'

The response confirms 4096 tokens are locked. Save the billing_session_id.

Step 2: Run your AI inference​

Execute the model call. Record the actual tokens consumed (e.g., 2187).

Step 3: Charge for actual usage​

curl -X POST https://<host>/services/user@example.com/charges \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "perform_authorization": false,
    "service_elements": [
      {
        "billing_session_id": "A1B2C461 4C5C21EF D47D5CBE AD918421",
        "session_id": "inference-req-xyz456",
        "service_type": "Quantity",
        "access_code": "TOKEN",
        "item": "Token",
        "units": 2187
      }
    ]
  }'

PortaBilling charges for 2187 tokens and releases the remaining locked tokens.

Pattern 3: Combined Authorize-and-Charge in One Request​

Use perform_authorization: true to have the gateway handle authorization and charging in a single API call. Useful for synchronous pay-per-query billing.

curl -X POST https://<host>/services/user@example.com/charges \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "perform_authorization": true,
    "service_elements": [
      {
        "session_id": "query-req-789",
        "service_type": "Quantity",
        "access_code": "QUERY",
        "item": "Query",
        "units": 1
      }
    ]
  }'

The gateway:

  1. Sends an authorization request to PortaBilling (checks balance/quota)
  2. If authorized, immediately sends an accounting request (charges 1 query)
  3. Returns the combined result

If authorization fails (e.g., quota exhausted), no charge is made and failed_service_elements contains the error. Your application can then return an appropriate error to the user (e.g., "You have reached your monthly query limit").

Billing Multiple AI Dimensions​

Some AI platforms charge multiple dimensions per request (e.g., input tokens, output tokens, and a per-request fee). Send all of them as separate service elements in one request:

curl -X POST https://<host>/services/user@example.com/charges \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "perform_authorization": false,
    "service_elements": [
      {
        "session_id": "req-multi-001",
        "service_type": "Quantity",
        "access_code": "INPUT_TOKEN",
        "item": "InputToken",
        "units": 800,
        "comment": "Input tokens"
      },
      {
        "session_id": "req-multi-001",
        "service_type": "Quantity",
        "access_code": "OUTPUT_TOKEN",
        "item": "OutputToken",
        "units": 742,
        "comment": "Output tokens"
      },
      {
        "session_id": "req-multi-001",
        "service_type": "Quantity",
        "access_code": "REQUEST",
        "item": "Request",
        "units": 1,
        "comment": "Per-request fee"
      }
    ]
  }'

Each element is billed independently. If any element fails, the failed elements appear in failed_service_elements.

Enforcing Token Quotas​

PortaBilling's Volume Discount Plans and Quotas are enforced in real time during authorization. If a user has consumed their free-tier allocation (e.g., 100,000 tokens/month), the next authorization will be rejected with:

{
  "error": "Authorization error.",
  "error_detail": "Requested quantity exceeds the allowed quantity of units."
}

Your application should detect this and offer the user an upgrade path.
