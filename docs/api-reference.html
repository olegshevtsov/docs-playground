API Reference

Base URL: https://<your-host> (or https://<your-host>/<BASE_PATH> if BASE_PATH is configured)

All endpoints except /health, /login, and /refresh-token require Authorization: Bearer <access_token>.

For interactive schema exploration, use the live Swagger UI at https://<your-host>/docs.

GET /health​

Health check. Returns the service status.

Authentication: Not required

Response 200:

{"status": "OK"}

Response 500: Configuration file cannot be read.

POST /login​

Authenticate and obtain access and refresh tokens.

Authentication: Not required

Content-Type: application/x-www-form-urlencoded (OAuth2 password flow)

Request fields:

FieldTypeDescription
usernamestringAPI username
passwordstringAPI password

Example:

curl -X POST https://<host>/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=api-user&password=api-pass"

Response 200:

{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_at": "2024-06-01T12:00:00"
}

Response 401: Invalid credentials.

POST /refresh-token​

Obtain a new access token using an existing refresh token.

Authentication: Not required

Request body (JSON):

{
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

Response 200: Same structure as /login response.

Response 401: Refresh token is invalid or expired.

POST /services/{user_id}/auth​

Authorize (pre-authorize) services for a user and lock the requested resources. The authorization reserves units in PortaBilling for the duration of the lock period. You must subsequently call either /services/{user_id}/charges or /services/{user_id}/unlock to complete or cancel the session.

Authentication: Required

Path parameter:

ParameterDescription
user_idThe Account ID of the user in PortaBilling (e.g., email, VIN, device ID)

Request body (JSON):

FieldTypeRequiredDescription
timestampstring (datetime)NoWhen the event occurred. Defaults to current time
service_elementsarrayYesList of services to authorize

Service element fields:

FieldTypeRequiredDefaultDescription
billing_session_idstringNoAuto-generatedUnique billing session ID (h323-conf-id format). Auto-generated from session_id if not provided
session_idstringNoRandomYour application's session identifier
commentstringNoWebCharging GWAdditional info for the transaction record
service_typestringYes—Type of service. See Service Types
access_codestringYes—Access code matching the product's usage charge in PortaBilling
itemstringYes—Rate code (destination) matching the tariff in PortaBilling
unitsintegerYes—Number of units to authorize/lock
lock_periodintegerNo300How long (seconds) resources remain locked if not explicitly released

Example:

curl -X POST https://<host>/services/EV-VIN-123456789/auth \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "service_elements": [
      {
        "session_id": "5d316f43-7689-4b88-a483-eab2843e272f",
        "service_type": "Quantity",
        "access_code": "ENERGY",
        "item": "KWh",
        "units": 50,
        "lock_period": 7200
      }
    ]
  }'

Response 200:

{
  "success": true,
  "service_elements": [
    {
      "timestamp": "2024-05-17 12:00:00",
      "billing_session_id": "7B6AA461 4C5C21EF D47D5CBE AD918421",
      "session_id": "5d316f43-7689-4b88-a483-eab2843e272f",
      "service_type": "Quantity",
      "access_code": "ENERGY",
      "item": "KWh",
      "user_id": "EV-VIN-123456789",
      "currency": "USD",
      "units": 50,
      "locked_units": 50,
      "lock_period": 7200,
      "expires_at": "2024-05-17 14:00:00"
    }
  ],
  "failed_service_elements": [],
  "unprocessed_service_elements": [],
  "error": "None",
  "error_detail": "None"
}

Response fields:

FieldDescription
service_elementsSuccessfully authorized elements
failed_service_elementsElements that were rejected (e.g., insufficient balance, invalid account)
unprocessed_service_elementsElements not attempted because a prior element failed
locked_unitsNumber of units actually locked by PortaBilling
expires_atWhen the lock expires if not released

Batch behavior: If any element in service_elements fails, the gateway automatically unlocks all previously authorized elements in the same request and does not attempt remaining elements. See Error Reference for details.

Response 400: RADIUS server unreachable or configuration error.

Response 401: Invalid or expired token.

DELETE /services/{user_id}/unlock​

Release locked resources before charging. Use this when a session is cancelled or abandoned after authorization.

Authentication: Required

Path parameter: user_id — same value used in the /auth request

Request body (JSON):

FieldTypeRequiredDescription
billing_session_idstringYesThe billing session ID returned by the /auth response
session_idstringYesThe session ID used in the /auth request
service_typestringYesSame as used in /auth
access_codestringYesSame as used in /auth
itemstringYesSame as used in /auth
commentstringNoOptional transaction note
timestampstringNoEvent timestamp

Example:

curl -X DELETE https://<host>/services/EV-VIN-123456789/unlock \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "billing_session_id": "7B6AA461 4C5C21EF D47D5CBE AD918421",
    "session_id": "5d316f43-7689-4b88-a483-eab2843e272f",
    "service_type": "Quantity",
    "access_code": "ENERGY",
    "item": "KWh"
  }'

Response 200:

{
  "success": true,
  "billing_session_id": "7B6AA461 4C5C21EF D47D5CBE AD918421",
  "error": "None",
  "error_detail": "None"
}

POST /services/{user_id}/charges​

Charge a user for consumed services. Can optionally perform authorization first.

Authentication: Required

Path parameter: user_id — the Account ID in PortaBilling

Request body (JSON):

FieldTypeRequiredDefaultDescription
perform_authorizationbooleanNofalseIf true, performs authorization for all elements first. All must succeed before any are charged
timestampstringNo—Event timestamp
service_elementsarrayYes—Services to charge

Service element fields: Same as /auth, but without lock_period.

perform_authorization behavior:

  • false — charges are applied immediately without prior authorization. Useful when authorization was already performed separately via /auth. Note: overdraft may occur if the account has insufficient balance.
  • true — authorization is attempted for all elements first. If all succeed, charging proceeds. If any fail, no charges are made and no funds are locked.

Example (charge without pre-authorization):

curl -X POST https://<host>/services/user@example.com/charges \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "perform_authorization": false,
    "service_elements": [
      {
        "session_id": "abc123",
        "service_type": "Quantity",
        "access_code": "TOKEN",
        "item": "Token",
        "units": 1500
      }
    ]
  }'

Response 200:

{
  "success": true,
  "service_elements": [
    {
      "timestamp": "2024-05-17 12:00:00",
      "billing_session_id": "7B6AA461 4C5C21EF D47D5CBE AD918421",
      "session_id": "abc123",
      "service_type": "Quantity",
      "access_code": "TOKEN",
      "item": "Token",
      "user_id": "user@example.com",
      "i_user": "12345",
      "units": 1500,
      "charged_units": 1500,
      "charged_amount": 0.15
    }
  ],
  "failed_service_elements": [],
  "unprocessed_service_elements": [],
  "error": "None",
  "error_detail": "None"
}

Key response fields:

FieldDescription
i_userPortaBilling's internal account ID (i_account)
charged_unitsUnits actually billed (may differ from units due to minimum billing rules or rounding)
charged_amountAmount charged in the account's currency

POST /raw-radius-authorization​

Advanced users only. Send a raw RADIUS Access-Request directly to PortaBilling. Use this for testing, debugging, or sending custom RADIUS attributes not supported by the standard endpoints.

Authentication: Required

Request body:

{
  "radius_body": {
    "NAS-IP-Address": "1.1.1.1",
    "User-Name": "123456",
    "h323-conf-id": "7B6AA461 4C5C21EF D47D5CBE AD918421",
    "call-id": "12345678-7689-4b88-a483-eab2843e272f",
    "Calling-Station-Id": "123456",
    "Called-Station-Id": "KWh",
    "PortaOne-Service-Type": "Quantity",
    "h323-ivr-out": [
      "PortaBilling_Ignore_Password:YES",
      "PortaBilling_AccessCode:ENERGY",
      "PortaBilling_Authorize:base=quantity;max=10;max_expires=10",
      "PortaBilling_Session:lock"
    ],
    "PortaOne-Charge": "report=1;commit=complete"
  }
}

All h323-ivr-out attributes must be provided as a list under the key h323-ivr-out.

Response 200:

{
  "success": true,
  "radius_response": {
    "h323-return-code": "0",
    "h323-ivr-in": ["PortaBilling_Authorize:base=quantity;avail=10;..."],
    "h323-currency": "USD"
  },
  "error": "None",
  "error_detail": "None"
}

POST /raw-radius-accounting​

Advanced users only. Send a raw RADIUS Accounting-Request directly to PortaBilling.

Authentication: Required

Request body:

{
  "radius_body": {
    "NAS-IP-Address": "1.1.1.1",
    "User-Name": "123456",
    "h323-conf-id": "7B6AA461 4C5C21EF D47D5CBE AD918421",
    "call-id": "12345678-7689-4b88-a483-eab2843e272f",
    "Calling-Station-Id": "123456",
    "Called-Station-Id": "KWh",
    "PortaOne-Service-Type": "Quantity",
    "Acct-Status-Type": "Stop",
    "h323-ivr-out": ["PortaBilling_AccessCode:ENERGY", "PortaBilling_Session:unlock"],
    "PortaOne-Charge": "report=1;commit=complete",
    "PortaOne-Used-Resource": "base=quantity;amount=1",
    "Acct-Delay-Time": 0,
    "Acct-Session-Time": 0
  }
}

Response 200:

{
  "success": true,
  "radius_response": {
    "PortaOne-Charge": ["entity-type=account;charged-amount=1.00000;charged-quantity=1", "..."]
  },
  "error": "None",
  "error_detail": "None"
}

POST /nchf-chargingdata​

Charge for services using the 3GPP Nchf (5G) charging interface. Accepts an Nchf-compliant JSON request and translates it internally to a RADIUS Accounting-Request for PortaBilling.

This endpoint is intended for platforms integrating with 5G core networks or for developers who want to use the Nchf schema for LTE/5G NETACCESS billing.

Authentication: Required

Request body: Nchf ChargingDataRequest JSON. The schema shown here is simplified. Refer to the live Swagger at /docs for the complete schema.

{
  "subscriberIdentifier": "imsi-234150999999999",
  "nfConsumerIdentification": {
    "nfName": "SMF-01",
    "nfIPv4Address": "10.0.0.1",
    "nFType": "SMF"
  },
  "multipleUnitUsage": [
    {
      "ratingGroup": 1,
      "usedUnitContainer": [
        {
          "serviceSpecificInfo": [{"value": "NETACCESS"}],
          "totalVolume": 1048576
        }
      ]
    }
  ]
}

The subscriberIdentifier maps to the user account in PortaBilling. The gateway processes only the fields that map to PortaBilling's RADIUS dictionary. Fields outside this mapping are accepted but not billed.

Response 200: Same structure as /services/{user_id}/charges response (AccountingResponse).

Response 400: RADIUS error or unmapped request data.
