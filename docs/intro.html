Overview

What Is the Web Charging Gateway?​

The Web Charging Gateway is a PortaOne add-on that lets modern web, cloud, and AI applications bill their users through PortaBilling — without writing a single line of RADIUS or Diameter protocol code.

It acts as a translator: your application sends standard HTTP REST requests, and the gateway converts them into the RADIUS protocol that PortaBilling uses internally.

Your Application
      │
      │  REST API (HTTP/JSON)
      ▼
Web Charging Gateway
      │
      │  RADIUS (UDP)
      ▼
 PortaBilling

What this means for you: You interact with a clean REST API and receive structured JSON responses. The gateway handles all RADIUS packet construction, session management, and protocol-level error handling.

Use Cases​

EV Charging​

Authorize and charge for energy consumption (kWh) and manage concurrent charging sessions. The gateway locks the requested energy quota before the session starts, preventing over-commitment, and releases any unused quota at session end.

Example: An EV charging station operator integrates with their fleet management platform. When a driver starts a session, the platform calls the gateway to authorize 50 kWh. The gateway checks the driver's PortaBilling account balance in real time and either grants the session or denies it immediately.

AI Service Monetization​

Track and bill resources consumed by AI models — tokens processed, API queries answered, voice engine minutes used. Enables pay-per-use and subscription quota models for AI-powered products.

Example: An AI API provider bills customers per token. After each inference call, the platform sends a charge request to the gateway with the token count consumed. PortaBilling applies the customer's tariff and deducts the cost from their account.

5G / LTE Network Services​

Handle usage data and accounting for mobile networks using NETACCESS service types. Also supports the 3GPP Nchf charging interface for integrations with 5G core network functions.

Example: An MVNO platform reports data session usage (bytes in/out) via the NETACCESS service type after each subscriber session closes.

General API and Cloud Services​

Monetize any modern web, SaaS, or video streaming platform with recurring or usage-based billing. Supports any metered resource that can be expressed as a countable unit.

Example: A video streaming platform bills minutes watched. A cloud storage provider bills GB stored per month. A SaaS platform bills API calls.

Why Online Charging?​

The Web Charging Gateway implements online charging — authorization and billing happen in real time, before or during service consumption. This is fundamentally different from offline charging (used in PortaOne's CDR Mediator), where usage records are collected and processed in batches after the service has already been delivered.

Online Charging (Web Charging GW)Offline Charging (CDR Mediator)
Authorization timingBefore service is consumedAfter service is delivered
Revenue protectionService denied if funds insufficientService already delivered before shortfall discovered
Quota enforcementReal time — cannot exceed thresholdPost-hoc — overage discovered in batch
Feedback to your appImmediate pass/fail per requestDelayed — batch reconciliation
ReconciliationNone neededCDR files must be collected, transferred, validated
ComplexityRequires auth → charge → unlock flowSimpler: collect usage records, batch-process

Key benefits of online charging:

1. Revenue leakage prevention Because authorization happens before consumption, the gateway can deny service to users with insufficient balance or expired quotas. With offline charging, the service has already been delivered by the time a shortfall is discovered — and in many cases (e.g., energy already delivered to an EV) recovery is impossible.

2. Real-time resource locking Resources (kWh, tokens, sessions) are locked when a session starts. This prevents multiple concurrent requests from over-committing the same credit pool. A user with a 100 kWh balance cannot simultaneously start three sessions each requesting 80 kWh.

3. Quota and threshold enforcement in real time PortaBilling's configured Volume Discount Plans and usage quotas are enforced at authorization time, not discovered after the fact.

4. Atomic multi-service billing When billing for multiple service elements in one request (e.g., energy + concurrent session slot), either all succeed or none proceed. Any partial failure automatically unlocks already-authorized elements, preventing split billing states.

5. No reconciliation overhead Every charge is confirmed synchronously. There are no CDR files to collect, transfer, validate, or reconcile — significantly reducing operational complexity.

6. Immediate feedback to your application Your application gets a structured JSON response with per-element success/failure status. This allows you to present real-time feedback to users (e.g., "Insufficient balance" shown to an EV driver before the charging cable activates).

When offline charging (CDR Mediator) is appropriate: Scenarios with very high transaction volumes, intermittent connectivity, or where post-hoc reconciliation is an acceptable business trade-off and real-time denial of service is not required.
