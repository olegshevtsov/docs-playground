Error Reference

HTTP Status Codes​

HTTP StatusWhen it occurs
200 OKRequest was processed. Check success, failed_service_elements, and unprocessed_service_elements for per-element results
400 Bad RequestRADIUS server unreachable, timed out, or a configuration-level error (not per-element failures)
401 UnauthorizedMissing, invalid, or expired Bearer token
422 Unprocessable EntityRequest body failed schema validation (Pydantic)
500 Internal Server ErrorGateway configuration cannot be read

Response-Level vs. Element-Level Errors​

The gateway distinguishes between two types of errors:

Response-level errors (error, error_detail at the top of the response):

  • RADIUS server unreachable or timed out
  • Gateway-wide processing failure

Element-level errors (within failed_service_elements):

  • PortaBilling rejected authorization for a specific service element
  • Account not found, insufficient balance, quota exceeded, unmatched destination

A 200 OK response does not mean all elements succeeded — always check the success field and the three element arrays.

Batch Failure Behavior​

When a request contains multiple service_elements and one fails, the gateway stops processing and does not attempt remaining elements.

Processing order:

  1. Elements are processed sequentially in the order given
  2. When the first failure occurs, processing stops
  3. Failed element → failed_service_elements
  4. Elements that were not attempted → unprocessed_service_elements
  5. Any elements that were already successfully authorized in the same batch are automatically unlocked

Example: A request with 3 elements where the second fails:

{
  "success": false,
  "service_elements": [
    { "access_code": "ENERGY", "locked_units": 50, "..." }
  ],
  "failed_service_elements": [
    {
      "access_code": "SESSION",
      "error": "Authorization error.",
      "error_detail": "Requested quantity exceeds the allowed quantity of units."
    }
  ],
  "unprocessed_service_elements": [
    { "access_code": "ADDON", "units": 1 }
  ]
}
  • Element 1 (ENERGY): authorized → automatically unlocked by the gateway
  • Element 2 (SESSION): failed → in failed_service_elements
  • Element 3 (ADDON): not attempted → in unprocessed_service_elements

Your application should: Treat any response with a non-empty failed_service_elements as a failure of the entire operation. Do not grant service.

Validation Errors (422)​

When the request body does not match the expected schema, the gateway returns 422 with Pydantic validation details:

{
  "detail": [
    {
      "loc": ["body", "service_elements", 0, "service_type"],
      "msg": "value is not a valid enumeration member; permitted: 'Voice', 'Data', 'Netaccess', 'Quantity', 'WiFi', 'Msg', 'Conference', 'Did', 'Iptv'",
      "type": "type_error.enum"
    }
  ]
}

Common causes:

  • service_type value not in the allowed enum
  • units is not an integer
  • Required fields (service_type, access_code, item, units) are missing
  • billing_session_id or session_id format issues

Checking for Errors in Your Application​

response = requests.post(url, json=payload, headers=headers)
data = response.json()

# 1. Check HTTP status
if response.status_code == 401:
    # Re-authenticate and retry
    ...

if response.status_code == 400:
    # RADIUS/connection error
    print("Gateway error:", data.get("detail"))

# 2. Check element-level results
if not data.get("success"):
    for failed in data.get("failed_service_elements", []):
        print(f"Failed: {failed['access_code']} - {failed.get('error_detail')}")
    # Do not proceed with service delivery
