Getting Started

This guide walks you through configuring the Web Charging Gateway add-on and making your first charge request in about 10 minutes.

Before you begin: Complete all steps in Prerequisites — the PortaBilling configuration must be in place before the gateway can process any requests.

Step 1: Configure the Gateway​

In the Add-on Mart portal, navigate to Add-on Mart Management > your REST API for Charging instance and open the Configuration page.

Fill in the required fields:

  1. Portal domain — enter the hostname for your gateway (e.g., charging-gw.example.com). Leave Generate certificates checked to enable automatic TLS.

  2. Under Authentication, select LocallyConfiguredUser and set:

    • Locally configured user login — the username your app will send to POST /login
    • Locally configured user password — a strong password

  3. Under RADIUS server configuration, enter:

    • NAS IP — the public IP registered as the Node NAS IP in PortaBilling
    • PortaBilling IP — IP address of the PortaBilling RADIUS server
    • PortaBilling Authorization port — 1812 (default)
    • PortaBilling Accounting port — 1813 (default)
    • PortaBilling secret — the RADIUS shared secret matching the Node entry in PortaBilling

  4. Click Deploy and wait for the status to show Success.

For the complete list of configuration fields, see Configuration Reference.

Step 2: Verify the Gateway Is Running​

Once deployment completes, verify the gateway is reachable:

curl https://<your-portal-domain>/health

Expected response:

{"status": "OK"}

Step 3: Authenticate​

All service endpoints require a Bearer token. Obtain one by logging in:

curl -X POST https://<your-portal-domain>/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=<locally-configured-user-login>&password=<locally-configured-user-password>"

Response:

{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_at": "2024-06-01T12:00:00"
}

Store the access_token — include it in every subsequent request.

Step 4: Make Your First Charge Request​

This example charges a user john.doe@example.com for 10 kWh of energy:

curl -X POST https://<your-portal-domain>/services/john.doe@example.com/charges \
  -H "Authorization: Bearer <your-access-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "perform_authorization": false,
    "service_elements": [
      {
        "session_id": "5d316f43-7689-4b88-a483-eab2843e272f",
        "service_type": "Quantity",
        "access_code": "ENERGY",
        "item": "KWh",
        "units": 10
      }
    ]
  }'

A successful response:

{
  "success": true,
  "service_elements": [
    {
      "timestamp": "2024-05-17 12:00:00",
      "billing_session_id": "7B6AA461 4C5C21EF D47D5CBE AD918421",
      "session_id": "5d316f43-7689-4b88-a483-eab2843e272f",
      "service_type": "Quantity",
      "access_code": "ENERGY",
      "item": "KWh",
      "user_id": "john.doe@example.com",
      "i_user": "12345",
      "units": 10,
      "charged_units": 10,
      "charged_amount": 1.50
    }
  ],
  "failed_service_elements": [],
  "unprocessed_service_elements": [],
  "error": "None",
  "error_detail": "None"
}
