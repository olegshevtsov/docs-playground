Configuration Reference

The Web Charging Gateway is configured through the Add-on Mart Management portal under REST API for Charging Configuration. Changes take effect when you click Deploy.

Domain Configuration​

FieldRequiredDescription
Portal domainYesThe public hostname for your gateway instance (e.g., charging-gw.example.com). Your application calls the API at https://<portal-domain>/.
Generate certificatesYesWhen checked, PortaOne automatically provisions and renews a TLS certificate for the portal domain. Leave checked unless you manage certificates externally.

CORS Configuration​

CORS (Cross-Origin Resource Sharing) controls which browser origins may call the API. These settings matter when your web application makes REST calls directly from a browser.

FieldDefaultDescription
CORS allow origins*Allowed origins (e.g., https://app.example.com). Use * to allow all origins (development only).
CORS allow origin regex(empty)Regular expression matched against the request Origin header, applied in addition to the explicit origins list.
CORS allowed methods*HTTP methods browsers may use (e.g., GET,POST,DELETE). Use * to allow all methods.
CORS allow headers*Headers browsers may send (e.g., Authorization,Content-Type). Use * to allow all headers.
CORS allow credentialsuncheckedWhen checked, browsers may include cookies or credentials in cross-origin requests. Do not combine with wildcard origins.
CORS expose headers(empty)Response headers exposed to browser JavaScript.
CORS max age600How long (seconds) browsers may cache preflight responses.

Production: Replace the wildcard * in CORS allow origins with your application's explicit domain. See Security Guide.

Authentication​

FieldRequiredDescription
Method of authenticationYesLocallyConfiguredUser — credentials stored in the portal configuration. BillingAdmin — credentials validated by PortaBilling's BillingAdmin API.
Locally configured user loginYes (LocallyConfiguredUser)Username your application sends to POST /login.
Locally configured user passwordYes (LocallyConfiguredUser)Password your application sends to POST /login.
Access token expiration timeYesAccess token lifetime in seconds. Default: 172800 (2 days).
Refresh token expiration timeYesRefresh token lifetime in seconds. Default: 2592000 (30 days).

When BillingAdmin is selected, the login and password fields are replaced by PortaBilling admin account credentials validated against the BillingAdmin API. See Authentication for details.

JWT signing secrets are automatically generated and managed by the Add-on Mart platform. You do not need to configure them.

RADIUS Server Configuration​

FieldRequiredDefaultDescription
NAS IPYes—The IP address the gateway identifies itself with in RADIUS requests. Must exactly match the NAS IP on the Node entry in PortaBilling.
PortaBilling IPYes—IP address of the PortaBilling RADIUS server.
PortaBilling Authorization portYes1812UDP port for RADIUS authentication (Access-Request).
PortaBilling Accounting portYes1813UDP port for RADIUS accounting (Accounting-Request).
PortaBilling secretYes—Shared RADIUS secret. Must exactly match the secret on the Node entry in PortaBilling. Use a strong value: mix of uppercase, lowercase, and numbers; maximum 32 characters.

The NAS IP and PortaBilling secret are the second security layer protecting all billing traffic. See Security Guide.
