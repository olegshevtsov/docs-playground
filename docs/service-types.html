Service Types

This document explains the three API fields that tell PortaBilling what to bill, which tariff to apply, and how much to charge. Understanding these is essential for correct integration.

service_type​

Determines the billing model — how consumption is measured and how PortaBilling tracks the session.

ValueDescriptionTypical use case
QuantityMetered resource billing. Charges for a discrete countable unitEnergy (kWh), AI tokens, API calls, storage GB
NetaccessNetwork access session billing. Tracks bytes transferred and session durationLTE/5G data sessions, Wi-Fi hotspots
VoiceVoice call billingVoIP calls
DataData service billingMobile data
WiFiWi-Fi service billingHotspot sessions
MsgMessaging billingSMS, MMS
ConferenceConferencing billingAudio/video conference sessions
DidDID number billingPhone number rental
IptvIPTV service billingVideo streaming

Most common for new integrations: Quantity (for metered APIs, EV charging, AI services) and Netaccess (for data/LTE sessions).

access_code​

Differentiates between multiple services or tariff plans that can be applied at the same endpoint.

What it maps to in PortaBilling: The Access Code field in a Product's Usage Charges section.

Who configures it: The PortaBilling administrator when setting up the product.

How it works: When a RADIUS request arrives, PortaBilling uses the access code to select the correct tariff from the product's usage charges. This allows one account to have multiple different billing rules — for example, an EV charging product could have:

  • Access code ENERGY → applies the kWh energy tariff
  • Access code SESSION → applies the concurrent session slot tariff

Example values: ENERGY, SESSION, TOKEN, DATA, VOIP, STORAGE

Rules:

  • Must exactly match the Access Code configured in PortaBilling (case-sensitive)
  • If there is no match, PortaBilling returns an authorization or billing error
  • Multiple service elements in one request can use different access codes

item​

Identifies the specific rate within a tariff — the "destination" or rate pattern that PortaBilling uses to look up the price per unit.

What it maps to in PortaBilling: The Called-Station-Id RADIUS attribute. PortaBilling uses this value as a Destination (rate code) to look up pricing in the assigned tariff.

Who configures it: The PortaBilling administrator when defining Destinations in the tariff.

How it works: The tariff contains a list of destinations, each with an associated price per unit. The item value in the API request must match one of these destination patterns. If no match is found, PortaBilling returns a billing error (typically unmatched destination).

Example values:

item valueMeaning
KWhPrice per kilowatt-hour
TokenPrice per AI/LLM token
MBPrice per megabyte transferred
QueryPrice per API query
MinutePrice per minute
GBPrice per gigabyte

billing_session_id​

A unique identifier that ties an authorization transaction to its corresponding accounting (charge) transaction in PortaBilling. PortaBilling uses this as the h323-conf-id RADIUS attribute.

Format: Space-separated hexadecimal groups following the h323-conf-id standard (e.g., 7B6AA461 4C5C21EF D47D5CBE AD918421)

Who provides it:

  • You can provide your own billing_session_id in the request
  • If you provide a session_id but not a billing_session_id, the gateway generates a deterministic billing_session_id from your session_id using an MD5 hash — you will always get the same billing session ID for the same session ID
  • If you provide neither, a random billing session ID is generated

Best practice: Always provide at least a session_id. This gives you a predictable, reproducible billing_session_id for correlating API calls to xDRs in PortaBilling.

Putting It Together​

Here is how the three fields combine in a real request:

{
  "service_type": "Quantity",
  "access_code": "ENERGY",
  "item": "KWh",
  "units": 15
}

PortaBilling processes this as:

  1. Find the account identified by user_id
  2. Find the product assigned to this account
  3. In the product's usage charges, find the entry with Access Code = ENERGY (access_code)
  4. The tariff linked to that usage charge contains a destination KWh (item)
  5. Apply the price per unit from the KWh destination to 15 units (units)
  6. Return the charged amount in the account's configured currency

If any step fails (account not found, access code not in product, destination not in tariff), the transaction appears in failed_service_elements with an error message.
