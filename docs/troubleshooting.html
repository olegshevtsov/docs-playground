Troubleshooting

All RADIUS Requests Fail (Timeout or No Response)​

Symptom: All /services/{user_id}/auth and /services/{user_id}/charges calls return 400 with "Timed out waiting for response from the RADIUS server".

Causes and fixes:

CauseFix
Wrong PortaBilling IPVerify the IP is correct and reachable from the gateway
Firewall blocking UDP 1812/1813Open UDP ports from the gateway's NAS IP to the PortaBilling server
NAS IP mismatchNAS IP in the portal must exactly match the Node's NAS IP in PortaBilling
Wrong PortaBilling secretPortaBilling secret must exactly match the secret on the PortaBilling Node entry

Verify NAS IP is registered in PortaBilling: Log into PortaBilling → Configuration → Nodes → confirm the NAS IP matches the value set in the portal.

401 Unauthorized on All Requests​

Symptom: Every API call returns 401.

Causes:

CauseFix
Token not includedAdd Authorization: Bearer <token> header
Token expiredUse POST /refresh-token to get a new access token
Wrong credentials at loginVerify Locally configured user login / Locally configured user password in the portal (LocallyConfiguredUser), or PortaBilling admin credentials (BillingAdmin)

"Invalid Account Number" Error​

Symptom: failed_service_elements contains "error_detail": "Failed - Invalid Account number".

Cause: The user_id path parameter does not match any Account ID in PortaBilling.

Fix:

  • Verify the Account ID in PortaBilling matches exactly what your application sends as user_id
  • Account IDs are case-sensitive
  • Check the account is active (not suspended or deleted)

"Requested Quantity Exceeds Allowed Units" Error​

Symptom: Authorization rejected with "Requested quantity exceeds the allowed quantity of units.".

Cause: The account has insufficient balance or has reached a quota/threshold.

Fix:

  • Check the account's current balance and credit limit in PortaBilling
  • Check if a Volume Discount Plan or Quota is configured on the product — the account may have consumed its allowed units for the current period
  • Reduce the requested units to a value within the available amount

"Unmatched Destination" Charge Error​

Symptom: failed_service_elements contains "error_account": "unmatched%20destination".

Cause: The item value in the request does not match any destination (rate code) in the account's tariff.

Fix:

  • Verify the item value exactly matches a destination defined in the tariff assigned to the account's product
  • Common mistakes: wrong capitalization (e.g., kwh vs KWh), typos, or using a destination not included in this tariff
  • Ask the PortaBilling administrator to check the tariff's destination list

Partial Batch Failure (Unexpected unprocessed_service_elements)​

Symptom: Some elements are in unprocessed_service_elements when you did not expect any failures.

Cause: An earlier element in service_elements failed, causing processing to stop. All subsequent elements become unprocessed.

Fix:

  • Check failed_service_elements to find which element failed and why
  • Processing is sequential — fix the root cause of the first failure
  • If elements have independent billing requirements and failures should not block each other, send them as separate API requests

Token Refresh Fails with 401​

Symptom: POST /refresh-token returns 401.

Cause: The refresh token has expired (default: 30 days).

Fix: Re-authenticate with POST /login using credentials.

CORS Errors in Browser​

Symptom: Browser console shows a CORS error when calling the API from a web application.

Fix:

  • In the portal under CORS configuration, add your application's origin to CORS allow origins
  • Or set CORS allow origin regex to match your origin pattern
  • Ensure CORS allow headers includes Authorization and Content-Type
  • Click Deploy after saving changes

Checking Logs​

Instance logs are available in the Add-on Mart portal under the History link next to the last deploy status. For detailed diagnostics, contact your PortaOne support team.
